⚙️ 核心设计模式

Agent 循环（s01 起）

  • LLM 调用 → tool_calls 判断 → 执行工具 → 追加 messages
  • while True 直到 finish_reason != tool_calls
  • 每轮记录完整 messages 变更日志
  • 双输出日志：彩色终端 + 纯文本文件 (agent_debug.log)

子智能体隔离（s04）

  • 父 Agent 调用 task 工具触发子 Agent
  • 子 Agent 启动时 messages=[]，全新上下文
  • 子 Agent 工具集去掉 task，防止无限递归
  • 子 Agent 完成后只返回文本摘要给父上下文

上下文压缩三层（s06）

  • micro_compact：每轮静默替换旧 tool_result 为占位符
  • auto_compact：超 token 阈值，LLM 生成摘要替换全历史
  • compact tool：模型主动调用手动触发压缩
  • 压缩前保存完整 transcript 到 .transcripts/

任务持久化（s07）

  • 任务存储在 .tasks/task_N.json，跨压缩周期存活
  • 支持 blockedBy / blocks 双向依赖图
  • 完成任务时自动从所有 blockedBy 列表移除
  • 使用 _atomic_write 防止崩溃时文件损坏

团队通信（s09-s10）

  • 成员配置存 .team/config.json
  • 通信通过 .team/inbox/name.jsonl 文件追加
  • 5 种消息类型：message / broadcast / shutdown_request / shutdown_response / plan_approval_response
  • s10 用 request_id 关联请求与响应

MCP 协议桥（s13）

  • 内嵌 FastMCP server 脚本，写入临时文件后子进程启动
  • 通过 stdio_client JSON-RPC 通信
  • mcp_list_tools() 自动转换 MCP schema → OpenAI format
  • agent loop 本身与 s01 完全相同，只换了工具来源

🔎 问题与改进建议

高 Token 估算对中文严重失准
s06 用 len(json_dumps) // 4 粗估 token 数。中文字符 1 个约占 1–2 token， 4 字符=1 token 的假设只适用于纯英文，实际阈值触发时机会大幅偏差，可能导致压缩过早或过晚。 建议引入 tiktoken 作可选依赖，降级时再回退字符估算。
影响文件：s06_context_compact.py（estimate_tokens 函数）
高 危险命令黑名单存在误杀与绕过风险
当前用字符串 in 匹配黑名单（如 "sudo"），会误拦截 pseudocode、cat sudoku.txt 等合法命令； 同时攻击者可用 s\udo、换行符等手法绕过。 建议改为 shlex 解析命令，仅匹配首个词，或使用正则精确匹配边界。
影响文件：所有 sNN 中的 run_bash() — 11 处
中 s09-s11 JSONL 收件箱写入缺少文件锁
多个线程可能同时追加写同一个 .team/inbox/name.jsonl，存在竞态条件， 可能导致 JSONL 行损坏（半行写入）。建议加 threading.Lock 或使用原子追加写。
影响文件：s09_agent_teams.py, s10_team_protocols.py, s11_autonomous_agents.py
中 工具调用串行执行，可并行的调用被浪费
LLM 有时一次返回多个无依赖的 tool_call（如同时读两个文件），当前所有 tool_calls 都是 for 循环串行执行。引入 ThreadPoolExecutor 并行执行无依赖工具调用可明显提速。
影响文件：所有包含 agent_loop 的文件
中 s06 的 auto_compact 使用纯文本截断，截断点可能切断 JSON 结构
conversation_text = json.dumps(messages)[:80000] 按字符截断，可能把 一条消息的 JSON 切断到中间，LLM 收到的是不合法 JSON。建议按消息边界截断： 先将 messages 从尾部裁剪到字符数限制内，而不是截断序列化字符串。
影响文件：s06_context_compact.py（auto_compact 函数，约第 133 行）
低 缺少 .env.example 示例配置文件
README 中列出了环境变量说明，但仓库中没有 .env.example， 新用户容易遗漏配置。添加一份带注释的示例文件可降低上手门槛。
建议新增：.env.example
低 s13 MCP server 脚本以字符串拼接嵌入，可读性差且难以维护
MCP_SERVER_SCRIPT 是把完整 Python 代码写成字符串常量， 没有语法高亮和 IDE 支持。建议改为 importlib.resources 或 textwrap.dedent + 多行字符串，或单独放在 _mcp_server.py 文件中。
影响文件：s13_mcp_tools.py（MCP_SERVER_SCRIPT 常量，第 101-171 行）
低 缺少公共模块 agent_utils.py，维护成本高
ColorFormatter、setup_logger、run_bash、run_read、run_write、run_edit、safe_path、 _msg_summary 在 14 个文件中几乎原样重复约 ~2,800 行。 可以提取为 agent_utils.py 共享模块，各脚本 import 即可， 同时不破坏"每个脚本独立可运行"的教学设计。
建议新增：agent_utils.py
